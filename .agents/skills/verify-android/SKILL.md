# Android の動作確認

検証は Android Studio とエミュレータで行う。実行していない確認は、通ったと報告しない。

`gradlew` は T-01a で追加される。まだなければ、実行できないことを報告する。

## 1. 単体テストとビルド

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

Windows の PowerShell では `./gradlew` の代わりに `.\gradlew.bat` を使う。失敗したら、テストを変更して通すのではなく原因を調べる。

## 2. エミュレータでの確認

- Device Manager で Play ストアまたは Google APIs のイメージを選ぶ。Play services がないとジオフェンスと撮影を試せない
- 変更した画面を実際に操作し、Logcat にクラッシュや例外がないことを確認する
- 保存内容は App Inspection の Database Inspector で確認する
- 空の状態、エラーの状態、ダークテーマも確認する

## 3. 権限

- 位置情報と通知を拒否してもクラッシュせず、店舗通知以外の機能が使えることを確認する
- 許可の状態は端末の設定かコマンドで戻す

```bash
adb shell pm revoke <パッケージ名> android.permission.ACCESS_FINE_LOCATION
```

## 4. ジオフェンス通知(T-07、T-12、T-16)

1. エミュレータの Extended Controls > Location で範囲の外に移動し、店舗を登録する
2. 位置情報を「常に許可」にする
3. 店舗の範囲外から範囲内へ位置を動かす。コマンドの場合は経度、緯度の順に指定する

   ```bash
   adb emu geo fix 139.7000 35.6800
   adb emu geo fix 139.7671 35.6812
   ```

4. Google マップなどで現在地を一度取得すると、位置の更新が届きやすい場合がある
5. 通知は数分遅れることがある。すぐ届かなくても、失敗と判断する前に数分待つ

次の場合もそれぞれ確認する。

| 条件 | 期待する結果 |
| --- | --- |
| なくなりそうな商品がある | 通知が届き、タップでリストが開く |
| なくなりそうな商品がない | 通知しない |
| 店舗の通知がオフ | 通知しない |
| 通知する時間帯の外 | 通知しない |
| 同じ日に同じ店舗へ再度入る | 2 回目は通知しない |
| 端末を再起動した後 | 監視が再開して通知が届く |

## 5. 報告
実行したコマンドと結果、確認した画面と条件、未確認の項目を PR に書く。実レシートの読み取り精度と実店舗での通知は、実機でしか確認できない。
