# プロジェクトのルール

レシートから消耗品の切れる時期を予測し、店舗の近くで通知する Android アプリを、複数人とエージェントが並行で開発している。

## 正とする文書
- 仕様は `REQUIREMENTS.md`、作業範囲は `TASKS.md`、設計は `PLAN.md` を正とする
- 要件にない機能を足さない。文書と食い違うときや仕様が読み取れないときは、推測で進めず人に確認する
- 人に確認するときは、方針を複数と推奨を提示する

## 作業範囲
- `TASKS.md` の「担当するファイル」の外は変更しない
- 範囲外の変更が必要になったら、作業を止めて人に伝える
- インターフェース、画面遷移、`AndroidManifest.xml`、依存ライブラリの変更は、小さな PR に分けて先にマージする
- データベースの項目を変えたいときは T-03 の担当に依頼する

## Git
- 1 タスク 1 ブランチ 1 PR とする。`main` に直接 push しない
- force push、PR のマージ、リポジトリ設定の変更は、人に頼まれたときだけ行う
- コミットの作成者には GitHub の noreply アドレスを使う

## コミットしてはいけないもの
- 実レシートとその画像
- 署名鍵とパスワード、API キー、トークン
- 個人のメールアドレスと住所、実在の店舗の位置情報を含むテストデータ

## プライバシー
- サーバーを追加しない。購入データとレシート画像を外部に送らない
- 購入データ、レシートの内容、位置情報をログに出さない
- レシート画像は保存後に削除し、データベースにも保存しない

## 報告
- 実行していないテストや確認を「通った」と報告しない
- 確認できなかったことは、確認できなかったと明記する
- エミュレータで確認できないこと(実レシートの精度、実店舗での通知)は、未確認として残す
